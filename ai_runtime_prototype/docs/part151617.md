# 15. Flow hien tai trong prototype

Prototype da di qua vong end-to-end tren host, nhung khac voi mo ta ban dau:
`backend_qnn_cli.c` (goi CLI `qnn-net-run`) khong con la duong chinh. Duong
chinh bay gio la `backend_qnn_api.c`, goi truc tiep QNN C API, khong qua bat
ky command-line tool nao luc runtime:

```text
Application C
    -> dl_init()
    -> dl_get_io_count(&input_count, &output_count)
    -> dl_inference_ex(input, &result)
    -> AI Runtime (ai_runtime.c)
    -> QNN API backend (backend_qnn_api.c)
    -> QnnContext_createFromBinary() + QnnGraph_execute()
    -> traffic_qos_model.bin  (context binary, KHONG phai .dlc)
    -> result.scores / result.label / result.latency_ms
```

Diem khac voi ban truoc:

- Input model cho runtime la **context binary `.bin`**, khong phai `.dlc`.
  `.dlc` chi la dau ra trung gian cua buoc convert; `.bin` moi la thu duoc
  "bake" san (qua `qnn-context-binary-generator`) va dong goi cung firmware
  khi deploy len thiet bi that.
- Kich thuoc input/output khong con hardcode (truoc day co macro
  `CLASS_NUM=5` co dinh). `dl_get_io_count()` doc dong tu metadata that cua
  context binary, nen runtime nay chay duoc voi bat ky model nao da convert
  vao pipeline (da test voi 2 model rat khac nhau: classifier 5 lop va
  detector ~151.200 so output) ma khong can sua/rebuild `main.c`.
- `dl_result_t` co them field `latency_ms` - thoi gian rieng
  `backend_execute()`, do bang `CLOCK_MONOTONIC`, dung de so sanh CPU vs HTP
  sau nay.
- `backend_qnn_cli.c` van con trong repo nhu tham khao/fallback, nhung
  khong phai duong duoc test/dung chinh nua.

Application khong goi truc tiep API cua QNN. Application chi include
`ai_runtime.h` va link voi `libai_runtime.a`.

File chinh:

```text
include/ai_runtime.h        API public cho application (co latency_ms)
src/ai_runtime.c            Quan ly init, inference, deinit, argmax, do latency
src/backend.h               Interface backend noi bo
src/backend_mock.c          Backend gia lap de test API nhanh
src/backend_qnn_cli.c       Backend qua qnn-net-run (con lai, khong con la duong chinh)
src/backend_qnn_api.c       Backend goi truc tiep QNN C API (DUONG CHINH)
examples/main.c             Application vi du, in label/scores/latency_ms
Makefile                    Build static library va example app (BACKEND=qnn_api|qnn_cli|mock)
tools/model_deploy.py        CLI: convert/build-context/run-api/deploy/...
tools/regression_test.py     Regression test tu dong cho bo model da biet
scripts/build_context_binary.sh  Sinh .bin tu .dlc (mot lan, tren host/CI)
```

Lenh chay nhanh nhat hien tai (thay cho `run_host_qnn.sh` cu, gio dung
duoc ca chuoi tu model goc):


Ket qua (vi du):

# 16. Tool CLI quan ly convert/build-context/run-api/deploy

`tools/model_deploy.py` da mo rong ra ngoai `convert/run-host/validate` ban
dau. Cac lenh hien co:

```text
convert         Convert .onnx/.tflite/.dlc sang artifact .dlc
run-host        Chay .dlc tren host bang qnn-net-run (duong cu, van giu de doi chieu/debug)
validate        run-host + so sanh voi reference output
build-context   Sinh context binary .bin tu .dlc (qnn-context-binary-generator)
run-api         Build BACKEND=qnn_api va chay traffic_app tren 1 context binary (DUONG CHINH)
deploy          Chain convert -> build-context -> run-api (+ so sanh reference neu co) - lenh "mot cua"
```

`deploy` la lenh nen dung hang ngay - nhan thang model goc (.onnx/.tflite/
.dlc), tu chay het cac buoc, tra ve JSON co `label`, `scores`, `latency_ms`,
va (neu co `--reference`) `validation_passed`.

Vi du deploy + validate:

```bash
cd /home/congtuan/qairt_sdk/ai_runtime_prototype
python3 tools/model_deploy.py deploy \
  --model /home/congtuan/model_test/traffic_qos_model.onnx \
  --input-raw /home/congtuan/model_test/input_seq.raw \
  --reference /home/congtuan/model_test/reference_output.raw \
  --backend cpu \
  --tolerance 1e-5
```

`run-host`/`validate` (duong cu qua `qnn-net-run`) van duoc giu lai - huu
ich de doi chieu ket qua CLI-based vs API-based khi nghi ngo loi o mot
trong hai duong, nhung khong con la duong deploy that.

## 16.1 Chuyen converter mac dinh sang QAIRT

(Khong doi so voi ban truoc - van con dung.)

Lenh `convert` mac dinh goi `qairt-converter` thay vi SNPE converter. SNPE
van duoc giu lai nhu compatibility fallback qua `--converter snpe`. Huong
production: QAIRT/QNN la duong chinh, SNPE chi la fallback.

## 16.2 Regression test tu dong

`tools/regression_test.py` chay `deploy` cho tat ca model trong bo test
(hien tai: `traffic_qos_model` va model YOLO `best.onnx`), assert
`validation_passed` cho tung model, in bang tong ket PASS/FAIL + latency.

Ly do can bo test 2 model tro len: mot bug (graph-name fallback) da ton tai
am tham vi truoc day chi test 1 model - bug chi lo ra o model thu hai. Co
it nhat 2 model khac han nhau (classifier nho vs detector lon) giup bat
duoc loai loi chi xuat hien o mot dang input/output cu the.

```bash
python3 tools/regression_test.py
python3 tools/regression_test.py --only traffic_qos_model
```

Them model moi vao bo test: sua `MODEL_CONFIGS` trong file, khong can sua
logic chay.

# 17. REST API prototype

`tools/model_deploy_server.py` van dung Python standard library, chua can
FastAPI. Endpoint hien co (KHONG doi so voi ban truoc):

```text
GET  /health
POST /convert
POST /run-host
POST /validate
```

**Gioi han can luu y:** server hien tai CHI expose duong `run-host`/
`validate` - tuc la van di qua `qnn-net-run` (CLI), KHONG phai duong
`build-context`/`run-api`/`deploy` (QNN C API truc tiep) da tro thanh
duong chinh o Phan 15/16. Noi cach khac, REST API dang "cham" hon CLI mot
buoc: CLI da chuyen sang API-based, REST server thi chua.

Day la viec con lai neu muon REST API phan anh dung production path: them
endpoint `POST /deploy` (va co the `/build-context`, `/run-api`) goi thang
`model_deploy.command_deploy` / `command_build_context` / `command_run_api`,
theo dung pattern `namespace_for_*` da co san trong file. Chua lam trong
prototype nay.

Chay server (khong doi):

```bash
cd /home/congtuan/qairt_sdk/ai_runtime_prototype
./scripts/run_api_server.sh --host 127.0.0.1 --port 8088
```
